# ربط رقم واتساب لمتجر جديد (كل متجر لديه رقمه الخاص كحساب أعمال جاهز)

هذا الدليل يغطي الحالة التي طلبتها: كل متجر عنده رقم واتساب خاص به مُفعَّل
مسبقًا كحساب أعمال (WABA) على فيسبوك، والمطلوب فقط ربطه بتوكن خاص بمتجره
داخل ميسور. لا علاقة له بمسار "Embedded Signup" الموصوف في
`docs/21-meta-tech-provider-guide.md` (ذاك مسار مستقبلي لجعل الربط ذاتي
الخدمة بالكامل بدون تدخل يدوي منك على الإطلاق — هذا الدليل هو المسار
اليدوي العملي المتاح الآن، ويعمل لعدد غير محدود من المتاجر).

## خطوة لمرة واحدة فقط (قبل إضافة أي متجر ثانٍ)

الكود الآن يدعم مسارًا واحدًا مشتركًا لكل المتاجر بدل مسار منفصل لكل متجر
(كان هذا يسبب تسرّب رسائل متجر إلى صندوق وارد متجر آخر لو أُضيف رقم ثانٍ
تحت نفس تطبيق Meta). قبل ربط أي متجر ثانٍ، نفّذ هذا التبديل مرة واحدة:

1. **أضف متغير بيئة جديد على Render:** `WHATSAPP_WEBHOOK_VERIFY_TOKEN` —
   أي نص عشوائي تختاره أنت (مثال: نفس أسلوب توليد `webhookVerifyToken`
   السابق، أو ببساطة نص عشوائي طويل). احفظه — ستحتاجه في الخطوة التالية.
2. من [developers.facebook.com](https://developers.facebook.com) → تطبيقك
   الحالي → **WhatsApp → Configuration → Webhook**:
   - غيّر **Callback URL** إلى: `https://<رابط-الباكيند-عندك>/v1/webhooks/whatsapp`
     (بدون أي معرّف حساب في آخر الرابط — هذا هو الفرق الجوهري).
   - غيّر **Verify Token** إلى نفس القيمة التي وضعتها في الخطوة 1.
   - اضغط **Verify and Save** — يجب أن ينجح فورًا (نفس آلية hub.challenge
     السابقة، فقط بمسار مختلف).
3. تأكد أن رقم متجر "غذائك" الحالي ما زال مشتركًا فعليًا عبر
   `POST /{WABA-ID}/subscribed_apps` (فعلتها سابقًا؛ لا حاجة لتكرارها إلا
   إذا غيّرت WABA أو App).
4. أرسل رسالة اختبار حقيقية على واتساب "غذائك" وتأكد أنها ما زالت تصل
   لصندوق الوارد كالمعتاد — هذا يثبت أن التبديل نجح دون كسر شيء قائم.

بعد هذه الخطوة، **لن تحتاج لمس إعدادات Meta App مرة أخرى أبدًا** عند إضافة
أي متجر جديد — كل ما يلي يتم من داخل ميسور والـ Business Manager فقط.

## خطوات إضافة كل متجر جديد (تتكرر لكل متجر، لا تحتاج مني كود جديد)

### 1. مشاركة حساب واتساب الخاص بالمتجر مع Business Manager الخاص بك

بما أن الرقم مُفعَّل بالفعل كحساب أعمال، عندك خياران:

- **الأسهل — نفس Business Manager:** إن كان بإمكانك إدارة حساب الأعمال هذا
  مباشرة (أنت من يملكه أو يديره)، فقط تأكد أنه مُضاف داخل نفس
  Business Manager الذي فيه System User الذي أنشأناه لـ"غذائك"
  (Business Settings → Accounts → WhatsApp Accounts).
- **إن كان المتجر يملك حسابه بنفسه:** من حساب Business Manager الخاص
  بالمتجر → Business Settings → Accounts → WhatsApp Accounts → اختر
  الرقم → **Assign Partner** (أو "Share") → أدخل **Business Manager ID**
  الخاص بك (تجده في Business Settings → Business Info). هذا يمنحك صلاحية
  الوصول للرقم دون نقل ملكيته.

### 2. تأكد من صلاحية System User على الرقم الجديد

من Business Settings → System Users → نفس "ميسور system user" المستخدم
لـ"غذائك" → **Add Assets** → أضف WABA الخاص بالمتجر الجديد مع صلاحية
Full Control (نفس الخطوات التي نفّذتها سابقًا لـ"غذائك"، فقط لرقم مختلف
هذه المرة).

> بهذا، **نفس Access Token الدائم** (System User Token) الذي تستخدمه الآن
> يعمل تلقائيًا لكل الأرقام المُضافة كأصول لهذا System User — لا حاجة
> لتوليد توكن منفصل لكل متجر إلا إذا فضّلت ذلك لأسباب تنظيمية (فصل الصلاحيات
> بين المتاجر). كلا الخيارين يعملان مع الكود الحالي.

### 3. اشترك الرقم في تسليم الأحداث (خطوة كانت السبب الجذري في مشكلة "غذائك")

عبر [Graph API Explorer](https://developers.facebook.com/tools/explorer/):

```
POST /{WABA-ID-الخاص-بالمتجر-الجديد}/subscribed_apps
```

باستخدام أي توكن له صلاحية على ذلك الـWABA. النتيجة المتوقعة:
`{"success": true}`. **هذه الخطوة تتكرر لكل متجر جديد** — Meta لا تفعّلها
تلقائيًا عند مجرد مشاركة الأصل.

### 4. اربط القناة من داخل ميسور

من "الإعدادات" → "ربط قناة جديدة" → واتساب:

| الحقل | القيمة |
|---|---|
| معرّف الحساب الخارجي (Phone Number ID) | Phone Number ID الخاص برقم المتجر الجديد (من Business Manager → WhatsApp Accounts → الرقم) |
| اسم العرض | اسم المتجر الجديد |
| Phone Number ID (في حقول الاعتماد) | **نفس القيمة أعلاه بالضبط** |
| Access Token | التوكن الدائم (من System User، أو توكن خاص بالمتجر إن اخترت فصله) |

اضغط "ربط القناة". لا حاجة لأي verify token هنا بعد الآن — ذاك كان جزءًا
من المسار القديم؛ التحقق الآن يتم مرة واحدة على مستوى التطبيق فقط (الخطوة
1 أعلاه).

### 5. اختبر

أرسل رسالة حقيقية من هاتفك إلى رقم المتجر الجديد وتأكد أنها تصل في صندوق
وارد **ذلك المتجر تحديدًا** داخل ميسور (وليس متجر آخر) — هذا يثبت أن
التوجيه بالـ`phone_number_id` يعمل بشكل صحيح.

# 🔴 التوكن المؤقت لا يصلح للإنتاج — اقرأ هذا أولًا

**رقم الاختبار (Test Number) الذي تمنحه Meta مجانًا يصدر توكنًا مؤقتًا
صلاحيته ٢٤ ساعة تقريبًا.** هذا هو السبب الأول والأشيع لجملة «كانت تعمل
أمس وتوقفت اليوم»: لا شيء تغيّر عندك، فقط انتهت صلاحية التوكن بصمت،
وMeta ترفض كل رسالة بعدها بالرمز **190 / 463**.

| | توكن رقم الاختبار | توكن System User |
|---|---|---|
| مدة الصلاحية | ~٢٤ ساعة | **دائم** (لا ينتهي) |
| المستلمون | ٥ أرقام مسجّلة يدويًا فقط | أي رقم |
| صالح للإنتاج | **لا** | نعم |
| من أين | لوحة Meta → WhatsApp → API Setup | Business Settings → System Users |

**توليد التوكن الدائم (مرة واحدة، ثم يخدم كل المتاجر):**

1. [business.facebook.com/settings](https://business.facebook.com/settings)
   → **Business Settings → Users → System Users → Add**.
2. سمِّه «ميسور system user»، والدور **Admin**.
3. **Add Assets** → WhatsApp Accounts → اختر WABA المتجر → **Full Control**.
4. **Generate New Token** → اختر تطبيق Meta الخاص بك → فعّل الإذنين
   `whatsapp_business_messaging` و`whatsapp_business_management` →
   **Generate**.
5. انسخ التوكن **كاملًا وفورًا** (لن يُعرض مرة أخرى)، وضعه في ميسور من
   «الإعدادات → القناة → تحديث بيانات الاعتماد».

> بعدها، أضف WABA أي متجر جديد كأصل لنفس System User — ونفس التوكن
> الدائم يعمل معه تلقائيًا (القسم 2 أعلاه).

# تشخيص الأعطال: العَرَض ← السبب ← الحل

**ابدأ دائمًا بزر «فحص القناة»** في: الإعدادات → القنوات → بطاقة القناة.
هو يتصل بـMeta مباشرة **بدون إرسال أي رسالة لأي عميل** (بخلاف «رسالة
اختبار» التي تحتاج مستلمًا، وتفشل لسببين مختلفين في آن واحد على رقم
الاختبار)، ويُخرج النتيجة بالعربية: صلاحية التوكن، ونوعه (مؤقت أم دائم)،
واسم الرقم وحالة توثيقه كما تراها Meta، ورابط الويبهوك المتوقَّع، وآخر
خطأ مسجَّل على القناة.

كما أن كل فشل إرسال صار يُسجَّل على القناة نفسها (`last_error`,
`last_error_at`, `token_expires_at`)، فتظهر حالتها الحقيقية في جدول «صحة
القنوات» في «نظرة عامة» بدل أن تبقى «متصلة» وهي متوقفة منذ أسبوع.

| العَرَض | السبب المرجَّح | رمز Meta | الحل |
|---|---|---|---|
| كانت تعمل ثم توقفت فجأة بلا تغيير من أحد، والرسائل الواردة **تصل** لكن لا رد يخرج | **انتهت صلاحية التوكن** — توكن رقم الاختبار عمره ٢٤ ساعة | `190` / subcode `463` | ولّد توكن System User الدائم (القسم الأحمر أعلاه) وحدّثه من «تحديث بيانات الاعتماد». لا تعتمد على توكن الاختبار في الإنتاج إطلاقًا |
| الرد يصل لرقمك أنت، ولا يصل لأي عميل آخر | **المستلم خارج قائمة أرقام الاختبار** — رقم الاختبار يراسل ٥ أرقام مسجّلة فقط | `131030` | أضف الرقم من: لوحة Meta → WhatsApp → API Setup → قسم To → Manage phone number list. الحل الجذري: انتقل لرقم أعمال حقيقي موثّق |
| الرد يخرج داخل المحادثة الحيّة، ويفشل إذا مرّ وقت طويل على آخر رسالة من العميل | **أُغلقت نافذة الـ٢٤ ساعة** لخدمة العملاء | `131047` (وأحيانًا `131026`) | خارج النافذة لا تسمح Meta إلا بقالب (Template) معتمد مسبقًا. جهّز قالب إعادة تواصل، أو انتظر رسالة جديدة من العميل تفتح النافذة |
| لا شيء يصل أصلًا — لا محادثات جديدة في الوارد، ولا رسائل عملاء منذ أيام | **الويبهوك لا يصلنا** (اشتراك ناقص أو Callback URL خاطئ) | لا يوجد خطأ — لا شيء يحدث | نفّذ `POST /{WABA-ID}/subscribed_apps` للرقم، وتأكد أن Callback URL في لوحة Meta = الرابط الظاهر في نتيجة «فحص القناة» بالضبط، وأن `WHATSAPP_WEBHOOK_VERIFY_TOKEN` مضبوط على الخادم. الفحص يميّز هذه الحالة بنفسه: «لم تصل أي رسالة عميل على هذه القناة» |
| فشل فوري لكل إرسال، وفشل «فحص القناة» من أول خطوة | **Phone Number ID خاطئ**، أو الرقم أُلغي تسجيله، أو التوكن بلا صلاحية على هذا الرقم | `100` / subcode `33` · `133010` · `10` | انسخ **Phone Number ID** من لوحة Meta → WhatsApp → API Setup (وليس WhatsApp Business Account ID)، وتأكد أنه نفسه في «معرّف الحساب الخارجي» وفي بيانات الاعتماد. وتأكد أن WABA مُضاف كأصل لـSystem User بصلاحية Full Control |

**أعراض أخرى تظهر في الفحص:**

| العَرَض | السبب | الحل |
|---|---|---|
| فشل متقطّع تحت الضغط | تجاوز حد الإرسال (`131056`, `130429`, `80007`) | أعد المحاولة، وارفع Messaging Limit بتوثيق العمل التجاري |
| توقّف كامل مع تنبيه في WhatsApp Manager | تقييد الحساب لأسباب سياسات/جودة (`368`, `131031`) | راجع Account Quality وقدّم Request Review من لوحة Meta |
| فشل مؤقت بلا رمز واضح | عطل لدى Meta نفسها | لا إجراء — أعد الفحص بعد دقائق |

> **ملاحظة أمنية:** نص خطأ Meta الخام (بما فيه معرّفات داخلية وfbtrace_id)
> لا يظهر أبدًا في أي واجهة للعميل أو للتاجر — يبقى في سجل الخادم وفي
> تفاصيل الفحص التقنية المرئية لطاقم المنصة فقط. ما يراه التاجر هو
> السبب مترجمًا وخطوة الحل فقط.

## ملخص الفرق عن الطريقة القديمة

| | قبل | بعد |
|---|---|---|
| رابط الـWebhook في Meta | واحد لكل متجر (يُعاد ضبطه في Meta لكل إضافة) | واحد ثابت للأبد لكل المتاجر |
| Verify Token | يُولَّد لكل متجر ويُلصَق في Meta | ثابت واحد، يُضبط مرة واحدة فقط |
| خطوة تلمس فيها إعدادات Meta App | مع كل متجر جديد | لا شيء — فقط Business Manager (مشاركة الأصل + الاشتراك) |
| خطر تسرّب رسائل بين متجرين | موجود بمجرد ربط متجر ثانٍ | غير وارد — التوجيه بمعرّف الرقم من داخل الرسالة نفسها |
